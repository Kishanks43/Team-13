# Sprint 3 Testing Deliverable Stories

## T-04: System Validation Report
- **ID:** T-04
- **Issue:** #70
- **Title:** T-04: System Validation Report
- **Owner:** Kishan K (`Kishanks43`)
- **Type:** Testing / Quality Assurance
- **Sprint:** Sprint 3
- **Points:** 2
- **User Story:**
  > As a quality engineer and team lead, I want a comprehensive System Validation Report evaluating the integrated Code Merge Simulator against all requirements defined in `docs/SRS_Team13.docx`, so that we have verified proof of compliance prior to the final release and demo.

### Scope & Description
The System Validation Report verifies that the end-to-end software system satisfies all functional requirements (FR-1 through FR-10) and non-functional requirements (performance, reliability, security, accessibility, usability):
1. **Verification of Core Workflows:**
   - Loading code (typing, pasting, sample loading, file uploads with format/size validation).
   - Line-by-line diff generation and side-by-side rendering with syntax markers.
   - Conflict detection and grouping into distinct conflict regions.
   - Conflict resolution options: Accept A, Accept B, Accept Both, and manual in-editor resolution.
   - Conflict navigation (prev/next, keyboard shortcuts `[` / `]`, conflict list jumping).
   - Undo/Redo session history operations.
   - Apply Merge guard preventing export while conflicts remain unresolved.
   - Exporting the merged result (clipboard copy, file download).
2. **Non-Functional Requirement Validation:**
   - Large file diff performance (2,000-line files in under 2 seconds).
   - Conflict counter latency (updates within 200 ms).
   - File upload rejection safety (binary and >2MB files refused safely).
   - XSS sanitization and safe rendering of arbitrary code payloads.
   - Immutability of input panes during merge operations.
   - Keyboard accessibility and color contrast compliance.
3. **Environment & Results:**
   - Browser compatibility matrix (Chrome, Firefox, Edge, Safari).
   - Pass/fail outcomes for all validation test scenarios.
   - Known limitations or deviations notes for the demo.

### Done When
- [x] Comprehensive validation test cases mapped to SRS requirements.
- [x] Execution results recorded with pass/fail status and evidence.
- [x] System validation report document saved to `docs/System_Validation_Report_Team13.docx` (and markdown summary).
- [x] Document reviewed and linked in repository documentation.

## T-05: Branch Coverage Report
- **ID:** T-05
- **Issue:** #71
- **Title:** T-05: Branch Coverage Report
- **Owner:** Kishan K (`Kishanks43`)
- **Type:** Testing / Metrics
- **Sprint:** Sprint 3
- **Points:** 2
- **User Story:**
  > As a developer and tester, I want a detailed Branch Coverage Report generated by Jest, measuring branch, statement, function, and line coverage across all engine and UI modules, so that untested conditional branches are identified and verified.

### Scope & Description
The Branch Coverage Report analyzes the test coverage of the entire application test suite using Jest's built-in Istanbul coverage collection (`npm test -- --coverage`):
1. **Metrics Collection:**
   - Percentage metrics for Statements, Branches, Functions, and Lines.
   - Module-by-module breakdown across `src/engine/` (`diff.js`, `conflicts.js`, `resolutions.js`, `session.js`, `history.js`, `manualEdit.js`, `merge.js`) and `src/ui/` (`diffView.js`, `conflictList.js`, `conflictNav.js`, `progress.js`, `exportMerged.js`, `undoKeys.js`, `paneInfo.js`).
2. **Branch Analysis:**
   - Examination of uncovered decision branches (e.g., edge cases in diff trimming, boundary conditions in conflict grouping, error handlers in file loading, clipboard API fallbacks).
   - Documentation of branch coverage adequacy thresholds (>90% target for engine logic).
3. **Report Artifacts:**
   - Tabular summary of all source files and their branch coverage percentages.
   - Analysis of branch coverage evolution between Sprint 1, Sprint 2, and Sprint 3.
   - Recommendations for any supplemental test cases.

### Done When
- [ ] Jest coverage report generated with full branch metrics (`npm test -- --coverage`).
- [ ] Comprehensive branch coverage report document saved to `docs/Branch_Coverage_Report_Team13.docx` (and markdown summary).
- [ ] Branch coverage percentages and uncovered branches documented per module.
- [ ] All critical engine branches verified with >90% branch coverage.
